TypeScript + TSX · WPF · ClearScript V8

Build Windows desktop apps with Jupiter.

A lightweight component framework that renders TypeScript components into native WPF controls.

Quick example

Quick example

Components use JSX, state, and native desktop APIs.

import { Button, Text, TextInput, View, desktop, useState } from "@jupiter/core";
export function HomeScreen() {
  const [name, setName] = useState("");
  return <View padding={16} gap={8}>
    <Text>Hello {name || "Jupiter"}!</Text>
    <TextInput id="name" value={name} onChangeText={setName} />
    <Button title="Copy name" onPress={() => desktop.clipboard.setText(name)} />
  </View>;
}

Architecture

1. TypeScript
Components live in src/.
2. Bundle
esbuild creates runtime/App.js.
3. Native runtime
ClearScript runs JavaScript in WPF. 
src/entry.ts -> packages/core -> runtime/App.js -> ClearScript V8 -> NativeBridge -> LayoutRenderer -> WPF

The current renderer performs full tree updates and keeps the JavaScript-to-native bridge intentionally small.

Window configuration

Pass initial settings from src/entry.ts:

start(App, {
  title: "My App", width: 1200, height: 800,
  minWidth: 800, minHeight: 500,
  maxWidth: 1600, maxHeight: 1000,
  resizable: true, titleBar: false,
  alwaysOnTop: false, fullscreen: false,
  startPosition: { type: "center" }
});
Option Purpose
title Initial native title.
width, height Initial dimensions.
minWidth, minHeight Minimum dimensions.
maxWidth, maxHeight Maximum dimensions.
resizable Enable or disable resizing.
titleBar Show or hide the title bar.
alwaysOnTop, fullscreen Initial window behavior.
startPosition center or manual with x/y.
Transparency: WPF transparency depends on native window style and rendering mode. Jupiter does not enable it automatically.

Components

Native-backed JSX components currently include:

Component Native mapping Main props/events
View, SafeAreaView Panel/layout padding, gap, direction
Text TextBlock fontSize, color
Button Button title, onPress
TextInput TextBox value, change/focus/submit events
ScrollView, FlatList ScrollViewer / children list and scroll props
Modal Overlay layout visible, onRequestClose
Switch, CheckBox, RadioButton Toggle controls value, onValueChange
Slider WPF Slider value, min/max, step
DatePicker, ProgressBar, ActivityIndicator WPF controls value/range/status props

Stable inputs

Give controlled inputs a unique id or testID. This preserves native identity across full renders. 

<TextInput id="email-input" value={email}
  onChangeText={setEmail} onSubmitEditing={submit} />

<Slider id="volume-slider" value={volume}
  minimumValue={0} maximumValue={100} step={10}
  onValueChange={setVolume} />

The slider is explicitly horizontal and left-to-right. The bridge detaches native sliders before reusing them to avoid the WPF logical-parent error.

State and effects

import { useEffect, useState } from "@jupiter/core";
const [count, setCount] = useState(0);
useEffect(() => {
  console.log(`Counter changed to ${count}`);
  return () => console.log(`Cleaning up ${count}`);
}, [count]);

Console calls are redirected through JupiterConsole. When started from a terminal, output uses the [Jupiter:log] prefix.

Navigation and route parameters

navigate("Profile", { name: "Ada", count: 3 });
export function ProfileScreen({ route, navigation }) {
  return <View padding={16}>
    <Text>Name: {route.params?.name}</Text>
    <Button title="Back" onPress={navigation.goBack} />
  </View>;
}

Use navigate, replace, and goBack. Register screens in NavigationContainer.

Native desktop APIs

Import the desktop object from @jupiter/core.

Window

minimize() · toggleMaximize() · toggleFullscreen() · toggleAlwaysOnTop() · restore() · close() · setTitle(title)

Clipboard

setText(text) · getText()

Files

openFile(filter) · saveFile(name, filter) · readText(path) · writeText(path, content)

System

openUrl(url) · showMessage(message, title) 
const file = desktop.files.saveFile("notes.txt", "Text files (*.txt)|*.txt");
if (file) {
  desktop.files.writeText(file, "Hello from Jupiter");
  desktop.showMessage(desktop.files.readText(file), "File content");
}
desktop.openUrl("docs/index.html");
Local paths: file:///docs means a root-drive path. Use docs/index.html for the project documentation.

Troubleshooting

Only one control is visible

A modal must be rendered as an overlay, not by placing every child in the same grid layer. The renderer now keeps normal content in a panel.

Slider logical-parent error

Use a stable slider id. The native bridge detaches old sliders before a full update.

Console output is missing

Run the app from a terminal. The GUI runtime attaches to its parent console and prefixes output.

Transparency is not allowed

Check the WPF window style and rendering mode. Unsupported transparency combinations are rejected by WPF.

Current limitations

  • Full tree updates instead of incremental UI reconciliation.
  • FlatList is not virtualized.
  • Accessibility mapping and style normalization are limited.
  • The desktop API is currently Windows/WPF-specific.
  • Automated tests, packaging, and production hardening are still evolving.
